## Notes

- **The hallucination metric is measuring nothing, and this is the finding of this run.** Its label set (`hallucinated-`, `nonexistent-`, `wrong-api`, `bad-citation`) matches zero bullets across 22 retros — yet this project has recorded **four** attested-total confabulation occurrences, the fourth on 2026-08-16 (`g-docs/todo.md` row 9: a runner claiming `565 passed, 5 failed` over a 17-row table summing to 537). The retros write this as "confabulation" / "invented a number" / "fabricated", none of which the spec's labels reach. Searching the language actually used finds it in 2 of 22 retros — which would score 9%, still ✓ in range, so **the profile is unaffected either way**. The defect is that the instrument would read 0% during an active confabulation streak. Fix belongs in `g-docs/telemetry-metrics.md` §1's Source line, not here — this skill follows the spec, it does not redefine it. Carry to `/g-patterns`.
- **Rework rate at 110% is the HOLD counter, not the code.** 24 accumulated review-holds against 31 `feat:` commits alone exceeds the ⚠ threshold before a single `fix:` commit is counted. Those holds are genuine (the `/g-resume` Step 0 work took six review rounds, every finding closed), but they are *review depth*, not shipped defects — the stricter regression regex reads 0% over the same period, and the last two milestones closed MERGE READY. The counter only resets on a `stable` profile, and `stable` requires zero ⚠, which this metric prevents: **the metric is now self-sustaining**. This is a scoring-loop defect worth an explicit decision (reset policy, or cap the holds term) rather than another snapshot noting it.
- **Review catch rate rests on one bullet.** 100% from a single `caught` bullet and zero `missed` bullets, unchanged across two runs and 6 retros of new corpus. Treat as decorative, not evidence.
