### Avoid / do differently
- **A scoped correction to the handoff leaves the same claim standing elsewhere in the block.** Four consecutive doc-gate HOLDs were all this one mechanic — the inbox correction reached two of six sites; a routing claim survived on the sibling label line; a `main = <hash>` binding was duplicated instead of replaced, stale copy first. The sweep that finally cleared it classified every claim-keyword hit across the whole block as either history or current-state assertion, instead of editing the clause that looked wrong.
- **`grep -c` is the wrong instrument for the §I format contract.** It counts matching lines, not occurrences, so a label appearing twice on one line reads as `1`. That false green passed the exact defect that broke the hook. The check that caught it was `grep -o | wc -l`, and behaviourally, simulating the consumer's own parse and reading what it emitted.
- **Each fix round generated the next round's defect.** The fix for round 1 contradicted the skill's own `## Rules`; the fix for round 2 mis-attributed provenance; the fix for the handoff broke a hook parser. This is the §A8 three-strikes shape and it is what triggered the park decision.
- **Universal consumer-facing rule text drafted from single-repo evidence did not survive review.** The three defects recorded in `g-docs/patterns-deferred.md` were: a trigger bound to the restated figure rather than the underlying detail, so the rule could not fire on the case it was mined from; a §G→§H cross-reference that the draft instructed be kept "in step if either is edited" while §H carried no reciprocal pointer back, making the upkeep unenforceable from the §H side, and that dangles for a project on the A–G preset where §H is absent; and a quiet-machine requirement unsatisfiable on hosted CI, containers, or shared executors, which collides with §H Tier 1.
- **An all-`DEFERRED` report published to the adversarial ingress yields boilerplate.** With nothing pending to argue against, all five returned verdicts were generic security-review checklists — threat model, PII, rollout plan, blast radius — none applicable to a process pattern report. One verdict stated the document contained no substantive content beyond its header.
- **External automation emitted an unsanitized filename that blocked integration.** n8n used a title string as a filename, producing `Adversarial review (REJECT): g-docs/patterns/latest.md`, which git parses as nested directories whose first component contains a colon — illegal on NTFS. `git merge origin/main` failed outright with `error: invalid path`, and the delivery could only be landed by building a sanitized commit through plumbing. The condition reproduces on any delivery carrying a title-derived name.
