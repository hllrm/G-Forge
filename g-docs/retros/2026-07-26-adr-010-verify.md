## Patterns

### Worked well
- **Executing the claim instead of reading it.** The `/g-tier light` check was the one the prior session flagged as taken from rules text; running it in a scratch repo settled it in one shot and produced a reusable fixture shape.
- **The doc gate earned its cost, repeatedly.** It refuted a wrong number I had published to four files, caught a supersession stamp that certified retired mechanics, and found the strongest misdirection in the record (`M41.md` — the next milestone's own `/g-plan` source telling a planner the arc runs its whole natural life as 2.x). None of that was reachable by diff review.
- **Adversarial framing of the re-review dispatch.** Telling each pass "verify these fixes, and here is the ground truth" rather than "re-review" is what surfaced propagation gaps instead of re-litigating settled points. Pass 5 got an explicit scope boundary (what counts as blocking vs. what belongs to the deferred re-scope) and returned 0 blocking without rubber-stamping.

### Avoid / do differently
- **Never sum by hand — this failed THREE times in one session, on the same number.** (1) A mental addition dropped a 5 and produced "518", which reached ADR-010, `.gitignore`, `CLAUDE.md` and the handoff before `doc-reviewer` refuted it against committed attestation records. (2) The same slip produced "the table sums to 517, so the headline sat 4 above it" — false; `CLAUDE.md`'s table summed to exactly 522 and agreed with its own headline, and both were simply one generation stale. (3) The corrected story then over-claimed "522 was the exact sum of the *declared headers*" — also false: two suites declare no header at all (59 assertions) and one declares twice, so a header sum is neither exhaustive nor unambiguous. Every total goes through `awk` on the run's own `Results:` lines; **only a run is authoritative**, and a derived provenance claim is as hand-made as a derived total. Recorded as a rule at `CLAUDE.md:31` — which is itself parked on exactly the gitignored, non-marker-fed surface the injection-rule decision above condemns, pending the generated-Quick-commands intake row. Note the third instance was handed to a reviewer marked "ground truth, do not re-derive" and it correctly re-derived anyway — an instruction not to verify is not evidence.
- **Verify by grepping what should be GONE, not what should be there.** A `sed` targeted a string that did not exist ("physical folder copy" vs the actual "folder-copied"), and the check grepped for the replacement — which was absent for the same reason the fix was. Passed, silently. Caught two passes later.
- **A fix list is not a blast radius.** Passes 3 and 4 both found the *same two decisions* unpropagated to files the previous fix list never named — `M44.md`, then `M41.md`. After deciding something, sweep for the claim's string class across the whole record, not across the files just edited.
- **Do not write a literal label into the line a hook parses.** The new handoff format note repeated `Active context:` on its own line; `workflow-checkpoint.sh:82`'s greedy BRE strips to the *last* occurrence, so the per-prompt banner served editorial prose instead of project state. The previous note had warned about exactly this.
- **Don't inflate a design observation into a defect.** "HQ writes the sentinel" was described as a hole; ADR-004's tree-binding already prevents stamping a different tree than the one reviewed. The residue is narrow and transcript-visible. Refinement, not defect.
