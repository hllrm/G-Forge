## Patterns
### Worked well
- Tightly scoped single-purpose review dispatches stayed cheap and fast across all five rounds (~68k–139k tokens, 3–9 min each); the reviewer verified claims against disk and caught real defects every round, including a self-inflicted count the dispatch prompt predicted.
- Fresh reviewer per round (single-use, never re-prompted); round 5 scoped to only the four fixed sites closed the gate in one pass.
- ADR-004 commit flow ran clean end-to-end: stage → stamp sentinel → commit via Write-tool message file → push; no gate denials, no heredoc failures.

### Avoid / do differently
- **Claim-dense durable documents spiral in review.** The 180-line draft carried ~40 hand-typed file:line/count claims; rounds went 6 → 2 → 4 blocking with each round's fixes introducing the next round's false claims (round 2's two blockers and round 3's four were all fix-introduced). The fix that worked was reducing the artifact's claim surface, not another fix round.
- **Unverified subagent claims propagated twice before being checked**: "claude-plugin can never be detected" (refuted by `g-specialize:92-93`) and "§I's membership is correct, only the clause is wrong" (refuted by `hooks/pre-commit:2-12`). Both were relayed to the developer as fact and corrected only by review. Verify set-membership claims against disk in the same turn they are made.
- **The overcorrection class**: a true narrow claim ("nothing checks CLAUDE.md:32's counts") was generalised to a false broad one ("zero prose currency checks exist in this repo" — Group D refutes it). Fix the claim at the width it was verified.
